# HOTFIX! Nexus Meltdown

A 16-bit style side-scrolling beat 'em up / platformer hybrid. You are **Alex "Bug" Voss**,
a senior engineer at Nexus Dynamics whose Friday deploy turned the company AI against everyone.
Fight through the office, the server farm and the cloud to the AI core, and roll it back.

- 4 stages, each introducing new mechanics, each ending with a boss
  (Chad Brockman the VP of Synergy, RACK-9000, SPAGHETTI.EXE, and N.E.X.U.S. with two phases)
- Beat 'em up combat: 4-hit chain, uppercut juggles, air kick, dive kick (pogo), dash strike,
  stomps, grab / knee / throw, and a HOTFIX special that uses the focus meter (or costs health)
- Platforming with momentum: coyote time, jump buffering, variable jump height, sprint,
  air dash, slopes, one-way platforms, moving platforms, springs, boost pads, fan updrafts,
  crumbling blocks
- Arena camera locks with enemy waves, combo counter with score multiplier and ranks
- Title, story, stage select, options (volume, difficulty), controls, pause, stage clear
  tally, game over with continues, ending and credits
- Chiptune soundtrack (9 songs) and synthesized sound effects
- **No dependencies, no build step, no binary assets.** Every pixel and every note is
  generated by code, so everything is editable as text.

## Running it

Open `game/index.html` in a browser. It works straight from the file system (plain `<script>`
tags, no modules). Or serve the folder:

```bash
python3 -m http.server -d game 8000
```

then open http://localhost:8000.

Useful URL parameters:

| Parameter  | Effect                                                              |
|------------|---------------------------------------------------------------------|
| `?stage=2` | jump straight into stage 2 (skips the menus)                        |
| `?unlock`  | unlock every stage in Stage Select                                  |
| `?debug`   | unlock everything and draw hitboxes (also toggled in game with F2) |

## Controls

| Action          | Keyboard                    | Gamepad      |
|-----------------|-----------------------------|--------------|
| Move            | Arrows / WASD               | D-pad, stick |
| Jump            | Z, Space, K                 | A            |
| Attack          | X, J                        | X            |
| HOTFIX special  | C, L                        | Y            |
| Dash            | Shift, V                    | B, RB        |
| Pause           | Enter, Esc, P               | Start        |

Moves: attack x4 is the chain (it only continues when a hit lands). Up + attack is the
uppercut (jump-cancel it to juggle). In the air: attack is a flying kick, down + attack is a
dive kick that bounces off what it hits. Attack while dashing or sprinting is a dash strike.
Land on enemies to stomp them. Walk into a reeling enemy (or keep pushing into one) to grab
it: attack knees, back + attack (or jump) throws it into its friends. Down + jump drops
through one-way platforms.

## Tech stack

Vanilla JavaScript, Canvas 2D and WebAudio. No framework, no bundler.

Why: the game needs only a tile map, sprites and a synthesizer, and a plain canvas gives exact
control of pixels at a native 320x224 resolution (the Mega Drive's). There is no build to
break, it opens anywhere, and it is easy to package later as a desktop app (Electron, Tauri or
NW.js just need to load `index.html`). Logic runs at a fixed 60 Hz timestep; rendering
happens once per display frame, and the canvas is upscaled by an integer factor with
`image-rendering: pixelated`.

## Code map

All files live in `game/src/` and share one global namespace, `G`. They are loaded in the
order listed in `index.html`.

| File            | Role |

| `audio.js`      | WebAudio synth: sound effect library (`G.Audio.sfx(name)`) and the music sequencer |
| `music.js`      | the soundtrack in tracker notation (`G.Songs`) |

| `themes.js`     | tilesets, props and parallax backgrounds per stage theme (`G.Themes`) |

## Core systems

### Game loop and scenes
`main.js` accumulates real time and calls `G.Input.update()` then `scene.update()` once per
1/60 s, then `scene.draw(ctx)`. A scene is any object with `update()` and `draw(ctx)`;
switch with `G.game.set(new Scene())`. `G.session` holds the run: score, lives, continues,
bits, current stage, checkpoint and difficulty.

### Physics and collision (`level.js`)
Bodies are `{x, y, w, h, vx, vy}` with `x` = center and `y` = feet. `level.move(body, plats)`
moves horizontally then vertically:
- walls: solid tiles block sideways movement, ignoring the bottom 8 px when grounded so you
  walk up slopes and small steps;
- floors: the highest surface between the old and new feet position. Slopes use the
  surface height at the body's center; one-way tiles only catch a body that was above them;
  moving platforms count as one-way surfaces and carry their riders. Grounded bodies snap
  down a few pixels so they stick to downward slopes;
- results: `onGround`, `ground` (`solid|oneway|slope|plat`), `hitWall`, `hitCeil`, `justLanded`.

### Player controller (`player.js`)
A state machine (`normal, attack, dash, special, grab, throw, hurt, downAir, down, getup,
dead, cutscene, win`), one `st_<state>` method each. Feel constants worth knowing:

| What | Value |
|------|-------|
| run / sprint speed | 2.6 / 4.3 px per frame (sprint after ~50 frames of running) |
| jump velocity | -6.7 (+ a bit more at speed), cut to -2.6 on release |
| gravity / max fall | 0.38 / 7 |
| coyote time / jump buffer | 6 / 6 frames |
| dash | 7 px per frame burst, 10 i-frames, 34-frame cooldown, one in the air |

### Combat
Attacks are data in `ATK` (`player.js`): duration, active frames, chain cancel frame,
hitbox, damage, knockback, launch, hitstun, hitstop and poses. A hit is an object passed to
`target.takeHit(hit, world)`:

```js
{ dmg, kb, kby, dir, stun, knock, breakGuard, heavy, type, from }
```

`takeHit` returns `true` (hit), `'block'` (guarded) or `false` (ignored). Enemies react in
`G.Enemy.takeHit`: hitstun, juggles while airborne, knockdowns with a bounce, death. Hitstop
(`world.hitstop(n)`) freezes the world for a few frames on impact, `world.shake(n)` shakes
the camera. Every landed hit calls `world.registerHit(dmg)` for the combo counter, which
multiplies the score of kills (up to x4) and fills the focus meter.

### Camera (`world.js`)
Follows the player with a look-ahead in the facing direction (bigger when sprinting), follows
the ground height vertically and only follows jumps near the screen edges. An arena or boss
fight sets `world.lock = {x0, x1}`, which clamps both the camera and the player.

### Level structure
A stage (`levels/stageN.js`) is a definition object:

```js
G.Stages.push({
  id, name, subtitle, theme: 'office'|'servers'|'cloud'|'core', music, bossMusic, tip, winQuip,
  intro: [[speaker, text], ...],            // dialog when the stage starts
  npcs: [{ who, lines, gift }],             // one per N marker, in order
  arenas: [{ waves: [['bot:L', 'blob:T:30'], ...], w: 20 }],   // one per A marker
  boss: { type, intro, outro, w },          // for the Z marker
  chunks: [String.raw`...`, ...],           // the map
});
```

The map is made of **chunks**: rectangles of characters joined left to right and aligned at
the bottom (end each chunk with the ground row and two fill rows). Legend:

| Char | Meaning | Char | Meaning |
|------|---------|------|---------|
| `#` | solid | `=` | one-way platform |
| `/` | 45° slope up to the right | `\` | 45° slope up to the left |
| `^` | hazard (wires, glitch spikes, plasma) | `1`-`9` | decorative prop of the theme |
| `@` | player start | `K` | checkpoint terminal (continue point) |
| `N` | NPC (next entry of `npcs`) | `A` | arena start (next entry of `arenas`; locks 20 tiles) |
| `Z` | boss arena start | `.` or space | empty |
| `g` | Glitchbot | `b` | Virus blob |
| `m` | Middle manager | `d` | Security drone |
| `f` | Firewall brute | `B` | breakable prop (random drop) |
| `C` | coffee (+25 HP) | `E` | energy drink (+15 HP, overclock, focus) |
| `P` | code patch (full HP) | `U` | 1UP |
| `o` | data bit (100 = 1UP) | `S` | spring |
| `>` `<` | boost pad | `H` `V` | moving platform (horizontal / vertical) |
| `L` | crumbling block | `F` | fan updraft |

Wave entries are `type:side:delay` with side `L` or `R` (materialize at that screen edge) or
`T` (drop from the top), and an optional delay in frames.

## Art pipeline

Everything is drawn by code into small canvases on first use, outlined (1 px dark line around
opaque pixels, the classic 16-bit look) and cached (`G.Gfx.sprite`). Stages pre-build every
pose they need when they load (`G.Art.prewarm`).

- **Palette**: named colors in `G.C` (`core.js`). Prefer these over new hex values.
- **Faces and portraits**: `HEADS` in `art.js` are pixel grids (one character per pixel with
  a palette). The same grid is the in-game head and, scaled 3x, the dialog portrait.
- **Bodies**: the pixel rig (`G.Rig` in `gfx.js`). A body is a hip, a torso and four two-bone
  limbs drawn as thick pixel lines. A `STYLE` (in `art.js`) gives bone lengths, colors and
  drawing functions for torso, head, limbs and held items; a `POSE` gives angles in degrees
  (0 = straight down, positive = forward). One pose table animates every character, so a new
  character is a style, and a new move is a pose or two. Run/walk cycles are generated.
- **Tiles and backgrounds**: `themes.js`. Each theme draws its tile kinds (`top`, `fill`,
  `oneway`, `slopeR`, `slopeL`, `spike`), its props and its parallax layers (canvases drawn
  once, scrolled at a fraction of the camera speed).

To design a sprite, edit its code and reload; a quick way to iterate is to draw a sheet of
sprites onto a canvas in a scratch HTML page that loads `core.js`, `font.js`, `gfx.js` and
`art.js`.

## Audio pipeline

- **Sound effects**: functions in `SFX` (`audio.js`) built from two primitives: `tone`
  (oscillator with a pitch sweep and decay) and `noise` (filtered white noise). Play with
  `G.Audio.sfx('punch')`.
- **Music**: `music.js`. A song is a tempo and sections played in `order`. A section gives
  one chord per bar (`'Am7 D7 Fmaj7 E7'`), a lead melody in note tokens (`c5`, `f#4`, `eb5`,
  `-` hold, `.` rest; eighth notes by default, `res: 1` for sixteenths), a bass style
  (`octave funk drive walk gallop sixteen hold`), an arpeggio style (`up updown none`) and a
  drum pattern (`rock disco break boss half four crash none`, `fill: true` on the last bar).
  Bass and arpeggios are generated from the chords. Four channels: pulse lead (with vibrato
  and echo), pulse arpeggio, filtered-saw bass, noise drums. `G.Audio.playMusic(id)`.
- Dialog "voices" are pitched blips per letter (pitch per speaker in `world.js`).

## How to extend

**Add a stage.** Copy a `levels/stageN.js`, change the data and chunks, and add a
`<script>` line for it in `index.html` (after the other stages). Stages are played in
`G.Stages` order.

**Add an enemy.** In `enemies.js`, extend `Enemy`, set its stats in `super(x, y, {...})` and
write `ai(w)` as a switch on `this.state` (use `setState`, `this.t`, `hitPlayer`, `front`,
`ledge`, `crowd`). Hit reactions, death, grabs and throws come from the base class. Register
it in `G.EnemyTypes`, give it a map character in `World.build` (`world.js`) and, if it uses
the rig, a style in `art.js`.

**Add a boss.** Extend `Boss` in `bosses.js` (it gets `this.arena = {x0, x1, gy}`), write
`ai(w)` with an `intro` state and its attacks, override `canStun()` / `shielded()` for its
weak points, register it in `G.BossTypes` and reference it from a stage's `boss.type`.

**Add a move.** Add an entry to `ATK` in `player.js` and a pose (or two) to `POSES` in
`art.js`, then start it from `startAttack` (or chain it with `next`).

**Add a pickup.** Add its effect to `PICKUP` in `objects.js`, a sprite to `items` in
`art.js`, and a map character in `World.build`.

**Add a song.** Add an entry to `data` in `music.js` and use its id in a stage's `music`.

**Add a theme.** Add an entry in `themes.js` with `sky`, `tile`, `props` and `layers`.

## Testing and debugging

- F2 (or `?debug`) draws hurtboxes (green/yellow) and active hitboxes (red).
- `G.step(n)` advances the simulation by `n` frames without rendering: handy from the
  browser console or an automated browser. `G.instance` is the running `World`.
- The game was smoke-tested with a scripted "autopilot" that plays every stage at full
  speed in headless Chromium (all four stages and bosses are clearable).
